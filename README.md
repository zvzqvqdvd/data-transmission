# 数据传输

**把人拉进同一个房间，就能互传文字、文件和桌面。加入的人什么都不用装。**

[![version](https://img.shields.io/badge/version-2.0.37-0078D4)](https://github.com/zvzqvqdvd/data-transmission)
[![platform](https://img.shields.io/badge/platform-Windows%2010%20%7C%2011-0078D4)](https://github.com/zvzqvqdvd/data-transmission)
[![size](https://img.shields.io/badge/download-9.07%20MB-07C160)](https://github.com/zvzqvqdvd/data-transmission)
[![dependencies](https://img.shields.io/badge/dependencies-none-07C160)](https://github.com/zvzqvqdvd/data-transmission)

> **在线使用**：<https://zvzqvqdvd.github.io/data-transmission/>
>
> 换域名或换托管时，只改程序目录的 `client_url.txt` 一行，刷新页面即生效，不用重新打包。

---

## 这是什么

一个「不注册、不登录、不租服务器」的临时互传工具。一方开房间，其他人扫码或输 10 位房间码进来，然后：

- 发文字——带时间和发送者编号，同一 WiFi 下通常几十毫秒上屏
- 发文件——多选、拖拽、粘贴都行，逐字节无损，同名自动加序号
- 投屏——把桌面共享给整个房间，1080p / 30fps

房间里最多 6 人。聊天记录只在内存里，房间结束即清空，不会在你的电脑上留下一份聊天存档。

**适合**：给同事传个大文件、手机和电脑之间倒东西、同一屋子的人互传、临时投个屏。
**不适合**：长期存档、账号体系、需要留痕的正式传阅、严格的政企内网（没有自建 TURN 中继）。

## 三种用法，按场景选

| 用法 | 需要准备 | 文件存哪 | 适合谁 |
|---|---|---|---|
| **纯网页房间** | 什么都不用装，打开主页即可 | 房主浏览器的 IndexedDB | 跨外网、临时传一次、不想装软件 |
| **局域网直传** | 房主下载 9 MB 的 [数据传输.exe](数据传输.exe) 并运行 | 房主电脑磁盘 | 同一 WiFi、要传大文件、要最快的速度 |
| **离线页面** | 把仓库里的 `index.html` 发给对方，浏览器直接打开 | 同「纯网页房间」 | 对方打不开在线页，或你想完全绕开托管 |

> 一句话记住：**创建房间可能需要房主跑一下程序，加入房间永远不用装东西。**

## 快速开始

### 一、创建房间

打开[主页](https://zvzqvqdvd.github.io/data-transmission/)，点「创建房间」，然后二选一：

| 选项 | 谁能进 | 要不要装东西 |
|---|---|---|
| `网页直连` | 有网就能进，可跨外网 | 不用，纯网页 |
| `局域网` | 同一 WiFi 更快，文件落到本机磁盘 | 房主跑 [数据传输.exe](数据传输.exe) |

选「局域网」而本机程序没在跑时，页面会自动切到下载引导：

1. 点下载（支持暂停 / 继续，走 Range 断点续传）
2. 双击运行，UAC 弹窗点「是」（放行 8000 端口）
3. 回到网页点「重新创建」

程序窗口里出现 `服务启动成功` 后，网页右侧会给出一串 **10 位房间码**，把它、邀请链接或二维码发给对方即可。**那个黑色控制台窗口别关，关了服务就停。**

> **局域网房间的外网默认是关的。** 要允许不在同一 WiFi 的人加入，房主在右侧「外网直连」卡上把「外网加入」拨开——地址和二维码在拨开的那一刻才生成。

### 二、加入房间

打开主页 / 房主发来的链接 / 扫二维码 → 输入 10 位房间码 → 点「连接」。手机、平板、Mac、Linux 都行。

连接前会真连一次：房间码不对、房间已结束、房主关着外网加入、房间已满，都会停在入口页说清原因，不会让你进一个收不到东西的空房间。刷新会直接在房间里恢复，不会先闪一屏起始页。

连接过程是**分段的**，提示行会一直写着「现在做到哪一步、已经等了几秒」（连信令 → 呼叫房主 → 等对方确认）。等得不耐烦就点那颗变成「取消」的按钮，不用干等到超时。万一失败，第二行会告诉你卡在哪一段、各花了多久——把那句话截图给房主，比说「连不上」有用得多。

> **外网设备只有主页这一条路。** 房主的 `127.0.0.1:8000` 只存在于房主自己电脑上，`192.168.x.x:8000` 只在同一 WiFi 内可访问。

### 三、开始传

| 想做什么 | 怎么做 |
|---|---|
| 发文字 | 底部输入框，Enter 发送 / Shift+Enter 换行 |
| 发文件 | 点输入框左侧的文件夹按钮、把文件拖进窗口，或直接 Ctrl+V 粘贴 |
| 下载别人的文件 | 消息卡片右侧的下载按钮，卡片下方有进度条 |
| 投屏 | 点输入框旁的显示器按钮；后进来的人会自动看到 |
| 清理空间 | 房主在「存储空间」卡上点「清理文件」，勾选后删除，立刻释放空间；聊天里的卡片会留下并标成「已清理」 |

发送队列会显示「等待 / 传输中（百分比 + 速度 + 剩余时间）/ 失败可重试」。外网访客发文件时，要等房主确认收全并落盘，才算真的成功。

**文件不做在线预览**——预览得先把整个文件拉过来，流量和等待都白花。所以消息里就是一张卡：扩展名、文件名、大小，加一个下载按钮。

## 界面导览

进房后右侧竖排，按房间类型挂卡：

| 房间类型 | 卡片（自上而下） |
|---|---|
| 网页直连 | 房间卡（徽标、房间码、剩余时间、销毁）→ 存储空间卡 → **外网直连卡**（邀请地址 / 二维码 / 设备清单） |
| 局域网（外网关，默认） | 房间卡 → **局域网卡**（`192.168.x.x:8000` / 二维码 / 设备清单）→ 外网直连卡收起（虚线灰底 + 灰色开关） |
| 局域网（外网开） | 同上，但外网直连卡展开：开关变绿，邀请地址、二维码、设备清单全出现 |

- 只有**房主**看得到设备数、对方 IP、倒计时和「外网加入」开关；访客和局域网设备没有这些
- **「存储空间 / 上传限制」卡房里所有人都看得到**：房主看实时已用与剩余，加入者看房主同步来的同一份数字（只读，附「还可上传多少」）。传输前就能知道这个房间装不装得下，不会传完才失败
- 局域网房间没有浏览器配额这回事，卡片只显示单文件上限
- 房间卡徽标写着 `网页直连` 或 `局域网`，手机上也保留
- 窗口宽度 ≤640px 时两张通道卡默认收成一行，点一下展开
- 顶栏三个按钮：网络与中继设置、房间说明、使用帮助

### 「外网加入」开关怎么工作

只在局域网房主的页面上出现，默认关：

- **关**：不注册 Peer、不碰信令服务器、不生成邀请地址，只有同一 WiFi 能进
- **开**：那一刻注册 `pc-<房间码>`，地址与二维码出现；之前发出去的老链接立刻可用
- **拨回关**：在线外网设备收到说明并退回起始页；之后再来敲门当场回绝，不会一直卡在「连接中」
- **房间码始终不变**，局域网 HTTP 完全不受影响

## 速度与断点续传

- **同一 WiFi**：走本机 HTTP 直传写盘，是三条路径里最快的
- **跨外网**：WebRTC 点对点，分片 64 KB 起（链路协商得好会自动放大到 128 KB），在途窗口 2 MB；没有经过中转服务器就不会被限速
- **断了不用重来**：外网下载中断后，已收的字节会保留，重连后房主从断点用 `Range` 接着发；万一文件在房主侧被改过，宁可从头重下也不会拼出一个坏文件
- **会慢的唯一常见原因**：双方都在对称 NAT / 公司网 / 校园网，ICE 只能落到公共 TURN 中继，速度由中继方带宽决定。访客侧会明确提示「速度受中继带宽限制，文件仍可正常传完」

## 数据存在哪、留多久

**局域网房间**（有本机程序）：

```
数据/房间/<房间码>/接收文件/
```

**聊天记录只在内存里，不落盘。** 一个房间一个文件夹，销毁时整个删除，**不可恢复**。

**纯网页房间**：数据和聊天都在房主浏览器的 IndexedDB 里，刷新能恢复，关掉页面就结束。容量按建房时的可用空间现算（总量的 80%，单文件不超过总量的 10%）。

销毁条件：房主点「销毁房间」、关掉房主页面、房主离线、或 60 分钟无任何通信。想留东西，销毁前把 `接收文件/` 拷走。

**空间不够不必销毁房间**：房主在「存储空间」卡上点「清理文件」，勾掉几个大文件即可，聊天记录和其他文件都保留。清掉的那些文件会以灰卡留在聊天里，标着「已清理」——记录不删，免得对方根本不知道有过这个文件。

## 常见问题

**Windows 提示「已保护你的电脑」**
下载栏点「…」→「保留」；运行时点「更多信息」→「仍要运行」。这不是查到病毒，而是没有代码签名证书、每个新版本的哈希都要从零积累声誉。嫌麻烦可以右键 exe → 属性 → 勾「解除锁定」。

**在微信 / QQ 里打不开**
点右上角「在浏览器打开」。内置浏览器通常不支持 WebRTC，也拿不到投屏权限。

**外网连不上**

| 页面提示 | 怎么办 |
|---|---|
| 找不到房间 | 核对 10 位房间码；确认房主页面还开着；局域网房间要房主拨开「外网加入」 |
| 外网已关闭 | 让房主打开「外网加入」，或改用同一 WiFi 的 `192.168.x.x:8000` |
| 连接超时 / 连不上信令服务器 | 换个网络或用系统浏览器；双方都在对称 NAT 时可能打不通，可在顶栏「网络与中继设置」里加一台自己的 TURN |

**投屏按钮点了没反应**
只有安全上下文（`https://` 或 `127.0.0.1`）能发起，`http://192.168.x.x` 不行。手机通常只能看，不能发。

**怎么确认下载的 exe 没被改过**
比对下方 SHA256：

```bat
certutil -hashfile 数据传输.exe SHA256
```

**页面看起来是旧版**
GitHub Pages 有 600 秒缓存。按 `Ctrl+Shift+R` 强刷；还不对就点顶栏「房间说明」，看底部「页面版本」是否等于下表的页面指纹。

## 已知限制

- 没有自建 TURN 中继，只内置两个公共 TURN 兜底；对称 NAT / 严格企业网络下仍可能连不上，可自行在设置里加一台
- 纯网页房间没有局域网 HTTP 入口，同一 WiFi 的设备也只能走 P2P（想走磁盘直传请用局域网房间）
- 房主是外网设备之间唯一的中转，房主关掉页面后外网设备之间就收不到彼此消息
- 外网访客只拿到最近 200 条历史；大文件传输期间房主需要保持页面打开
- 局域网 `http://<IP>:8000` 是明文 HTTP，不适合传敏感数据
- 局域网房间单文件上限 4 GiB（可用环境变量 `DATATRANSMISSION_MAX_FILE_SIZE` 调整）；纯网页房间按可用空间动态计算
- 没有管理面板，也不能单独踢人；想一次清空就「销毁房间」再重新创建

## 版本与校验

| 项目 | 值 |
|---|---|
| 当前版本 | **2.0.37** |
| `index.html` | 553,484 B / md5 `f607a1cc` |
| `数据传输.exe` | 9,508,623 B（9.07 MB）/ sha256 `101fed69…7ee46` / 版本资源 2.0.37.0 |
| 页面指纹 | `66bb7c6f0b` |

**2.0.37 做了什么**：全量排查了一遍「平时不报错、出事就崩在关键路径上」的写法。

- **修掉一个真实崩溃**：访客渲染文件卡片时引用了一个只在 else 块里存在的变量，每收到一条文件消息就抛一次 `ReferenceError`。而这个崩溃点正好在「文件已经发送成功、正在把卡片画进列表」之后——所以现象就是**上传显示失败、房主却已经收到了**。现在把判断提到分支外面，并由渲染回归测试盯着
- **暂停中连接断开不再卡死**：暂停后如果房主关了房间，分片循环只在等「继续」，永远不退出，发送队列会一直显示「正在发送中」，下一间房连按钮都点不动。现在暂停期间会检查连接，断线立刻收手
- **三处「先用后声明」**：`waitChange` / `waitDrain` / `probeRoom` 里的定时器和回调原来引用的是后面才声明的 `const`。目前都跑在异步回调里，暂时没事，但同步触发一次就会抛异常。全部改成先声明
- **发送队列有兜底**：队列本身出意外时不再变成一个没人处理的 Promise 拒绝，会提示「请刷新页面后重试」并附带页面版本
- **新增三道自动检查**：`tests/no-undef.mjs`（语法树级找「引用了但没声明」）、`tests/risk-scan.mjs`（JSON 解析未保护、DOM 空引用、重复绑监听）、`tests/render.test.mjs`（各种消息形态真跑渲染）

**2.0.36**：一条原则落地——**送达就是送达，界面出错不许改判**。

- **送达标记优先于任何异常**：以前防「已送达却报失败」靠的是给每个收尾动作包 `try/catch`，新加一处界面代码漏了就会复发。现在引入 `delivered` 标记：字节和回执一到位就置位，之后无论抛什么错，这条文件都按「已发送」处理，只在控制台留一行记录。这类误判从此在结构上不可能发生，而不是靠人记得住
- **脚本错误不再原样甩给用户**：失败行不再出现「X is not defined」这种只有开发者才看得懂的字，改成「页面脚本出错，请按 Ctrl+Shift+R 强制刷新后重试（页面版本 xxxx）」
- **页面指纹换了**：`693d53e3b0`。如果你在「房间说明」底部看到的不是这一串，说明浏览器还在用旧页面，本次修复对你无效

**2.0.35**：把「房间没了」和「发送失败」这两件事说准。

- **房间没了就真的离场**：以前判「房间已结束」只数「连续查不到几次」，中间夹一次超时就清零，「查不到 → 超时 → 查不到」能无限循环——界面永远停在「② 已连到信令，正在呼叫对方设备…」，房间早就没了人还在里面。现在加了 20 秒硬上限，从第一次查不到起最多确认 20 秒，到点退回起始页并说明原因
- **不再假装还在呼叫**：一旦确认过「信令里没有这个房主」，状态行改说「正在确认房间是否还在…」，下面还写着还剩几秒，不再拿 ② 那句话误导人
- **房主悄悄消失也能发现**：加入者这边新增心跳，每 15 秒敲一次，连续两次没回音（约 30 秒）就判这条链路已死并重连。房主直接关页面、断网时不会再出现「房间没了、人还留在里面」
- **加入者终于会回 PONG 了**：以前加入者收到房主的 PING 拿不到连接对象，从来没回过 PONG，安静的设备会被房主按超时摘掉（表现是「待一会儿突然被踢」）

**2.0.34**：把「点连接之后那十几秒」从黑箱变成看得见的过程。

- **分段实时提示**：连接时提示行一直写着第几步、已等几秒，不再是一句「正在连接…」顶到底
- **随时可取消**：等待期间那颗按钮变成「取消」，点了立刻停下，输错房间码不用干等满 12 秒
- **房主刷新不再被误判**：第一次查不到房间不会当场判死，等 0.9 秒再确认一次，两次都找不到才说「房间不存在」
- **打洞失败立刻收手**：网络连不通时当场告诉你，并建议同一 WiFi 改用局域网房间，不再让你对着进度条等到超时
- **满员就说满员**：房间满了会明确写「已满（最多 6 人）」，不再含糊成「没有回应」
- **房间码当场校验**：不足 10 位立刻提示，不发请求、不等待
- **失败带诊断**：第二行显示「信令 0.8s · 呼叫 0.4s · 共 2.0s」，截图就能定位问题在哪一段

**2.0.33**：清理保留记录（灰卡 +「已清理」），上传可以暂停 / 继续 / 取消。

- **清理不再抹掉记录**：房主清理文件后，聊天里那张卡片还在，只是变成灰卡并标上「已清理」，点下载才提示原因。以前是连记录一起删掉，对方连「这里曾经有过一个文件」都不知道，只能跑来问你
- **已下载过的人不受影响**：访客如果先前已经拉过这份文件，本地副本还在，卡片照常可以再存一份
- **上传可以暂停 / 继续 / 取消**：外网发送时，待发送列表每一条右侧有暂停键和取消键，按暂停后进度停住不动，继续时从下一片接着走，不重传
- **取消会通知对端**：对方立刻丢掉半截缓冲，不会干等到超时，也不会收到一个坏文件
- **房主上传如实说明**：房主那条是一次 HTTP 上传，浏览器不支持「停下来再从中间续」，所以按钮会直接告诉你不能中断，不假装备一个按了没反应的键

**2.0.32**：存储配额对加入者可见，并支持房主清理文件腾空间。

**2.0.31**：断点续传。外网下载中断后从已收字节处接着下，接缝前先验文件长度与已收字节，宁可重下也不拼坏文件；访客侧新增中继提示。

| `数据传输.exe` | **构建产物**，Windows 本机程序，内含同一份 `web/` |
| `web/` | 前端源码（8 个文件），改界面只改这里 |
| `数据传输.py` | 后端源码：HTTP 服务、房间状态、上传下载、页面构建 |
| `tests/` | 六套测试，共 195 项 + 两个静态检查 |
| `client_url.txt` | 在线地址的单一来源（CORS、邀请链接、二维码、下载地址都由它推算） |
| `ARCHITECTURE.md` | 架构、协议、构建发布 SOP、给后续接手的人看 |

自己构建（Windows，需要 Python 3.7+ 与 Node）：

```bash
python 数据传输.py --export-page     # 由 web/ 重新生成 index.html
python tests/smoke.py                # 后端冒烟 66 项
node tests/cloud_store.test.mjs      # 云仓库 44 项
node tests/transfer.test.mjs         # 传输层 31 项
node tests/join.test.mjs             # 加入探活 38 项
node tests/render.test.mjs           # 消息渲染 16 项
node tests/no-undef.mjs              # 未声明变量，必须 0
node tests/risk-scan.mjs             # 同类隐患清单（信息性）
```
