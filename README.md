# 数据传输 v2

Windows 免安装临时互传工具。**完全重写的新项目**：现有目录只作为功能与界面的需求参照，
不导入、不复制、不调用、不打包其中任何文件。

与参考样本**唯一的区别**：入口页「创建房间」下方多了一个**默认不勾的「开启局域网访问」按钮**
（按钮旁边一行文字引导）。不开启时创建房间零软件依赖；开启后点创建才检测本机程序，
没启动时切到现有的引导下载页面。房间本身始终只有一种：房间码前端生成、消息与文件只存房主浏览器内存、
生命周期由房主页面管理。

## 目录

```
数据传输-v2/
├── index.html          构建产物：单文件零外链入口页（部署到 Pages / 发给访客）
├── 数据传输.py         本机程序（全新极简实现）+ 页面构建
├── 数据传输.exe        打包产物，仅开启局域网时才需要
├── client_url.txt      在线页地址（改这里即生效，不用重打包）
├── version_info.txt    exe 版本资源
├── README.md
└── web/                六文件源码，全部新写
    ├── page.html       DOM 外壳 + 构建占位符
    ├── app.css         全部样式（1099 / 1100 / 640 三档断点）
    ├── vendor.js       PeerJS 1.5.4 + qrcode-generator 1.4.4（仅上游第三方库）
    ├── app.js          常量、内存仓库、会话快照、P2P 配置、串行发送、工具
    ├── room.js         房间运行时：内存数据源、P2P、文件分片、共享、局域网桥、生命周期
    └── gate.js         入口页：创建 / 加入 / 局域网按钮 / 检测 / 下载引导 / 启动分发
```

三个业务 JS 按 `app.js → room.js → gate.js` 拼进同一个 `<script>`、共用全局作用域，
`--export-page` 把它们与 CSS / vendor.js 内联进根目录 `index.html`。
**不要直接编辑 `index.html`**，改 `web/` 后重新导出。

## 快速开始

```bash
# 1. 生成单文件页面（改过 web/ 或 client_url.txt 后都要跑）
python 数据传输.py --export-page

# 2. 纯外网使用：把 index.html 部署到 Pages（或任意静态托管），直接打开即可。
#    创建房间不需要任何本机程序。

# 3. 需要局域网时：在这台电脑上运行本机程序（建议以管理员身份，放行防火墙需要）
python 数据传输.py
#    或打包后双击 数据传输.exe

# 4. 打包 exe（需 pyinstaller，注意 --add-data 与 --version-file 用绝对路径）
pyinstaller --onefile --noconsole ^
  --add-data "D:\ruanjian\wangzhan\数据传输-v2\web;web" ^
  --version-file "D:\ruanjian\wangzhan\数据传输-v2\version_info.txt" ^
  "D:\ruanjian\wangzhan\数据传输-v2\数据传输.py"
```

打包前先删 `build/` `dist/`；改过 `web/` 必须重新执行 `--export-page`。
`client_url.txt` 由程序按 mtime 热读，改地址不用重打包。

**部署时三件事**：
- 把 `index.html`、`数据传输.exe`、`client_url.txt` 放在同一个静态目录（GitHub Pages 仓库）。
  下载引导页的地址 = 在线页基地址 + `数据传输.exe`，所以 exe 必须与页面同目录。
- 本机程序给同 WiFi 设备托管的页面，读取的是 exe 同目录的 `index.html`；改过 `web/` 要重新导出并替换。
- 放行 8000 端口通常需要管理员权限；未提权时本机回环仍可用，但同 WiFi 设备可能被系统防火墙拦截。

## 使用流程

| 场景 | 操作 |
|---|---|
| 纯外网创建 | 入口页直接点「创建房间」→ 前端生成 10 位房间码 → 发邀请链接 / 二维码 |
| 加入房间 | 打开邀请链接或手输房间码 → 点对点连到房主 |
| 开启局域网 | 点入口页「开启局域网访问」按钮（旁有文字引导）→ 点「创建房间」→ 自动检测本机程序 |
| 程序没启动 | 自动切到引导下载页 → 下载 `数据传输.exe` → 双击运行 → 回来点「重新创建」 |
| 同 WiFi 设备 | 从房主侧栏的局域网地址打开页面 → 走本机程序内存转发，断外网也能用 |
| 销毁房间 | 房主主动点「销毁房间」，或真正关闭页面，或 30 分钟内房间内无人通信 |

按钮可再点一次关闭；关闭后就是纯外网创建，零本机请求。房间内没有第二个开关。

## 本机程序只做四件事

1. `netsh` 放行 8000 端口
2. 看门狗：主进程退出 / 崩溃后回收规则（另有 `atexit` 兜底）
3. 托管同一份页面，给同 WiFi 设备一个 `http://192.168.x.x:8000` 地址
4. 内存接入转发：`attach / poll / push / send / file / detach`

**它不生成房间码、不接收或存储任何消息与文件到磁盘、不写聊天记录或接收文件目录、
不发心跳、不判定房间死活、不销毁房间。** 房主页面把已生成的房间码告知程序只是用于转发路由。

浏览器页面不能监听端口，所以放行防火墙之外必须有这个最小服务，但它只是通道，不是数据源。

## 房间规则

- 房间码前端 `crypto.getRandomValues` 生成 10 位（不含易混字符），Peer ID 仍为 `pc-<10位码>`
- 邀请链接 `?room=<码>&v=<页面指纹>`，指纹 = 六文件 md5 前 10 位，改任一前端文件链接就会变
- 消息与文件只存房主浏览器内存：不落盘、不写 IndexedDB、不写 sessionStorage 二进制
- **刷新不关闭、不销毁**：sessionStorage 只存轻量 JSON 快照（房间码、文本、成员、`startedAt`、
  `lastActivity`、接入状态），刷新后同一个码重新注册 Peer，**绝不换码**；文件二进制无法跨刷新，
  卡片标「文件已失效，需重新发送」
- 30 分钟口径：房主 / 任一外网访客 / 任一局域网设备发出的文字、文件、成员变动都刷新计时；
  心跳、PING、探活、开关操作不算；刷新不重置计时
- 访客断线进入 60 秒重连宽限；房主主动销毁时显式广播 `ROOM_CLOSED`
- 销毁 `destroy(reason)` 一次性清：Peer 与连接、消息与文件 Map、ObjectURL、会话快照、
  定时器、DOM、局域网接入通道，并通知各端同步清空

## 硬约束（改动时别踩）

- `CHUNK_SIZE = 15000` 必须 < PeerJS `chunkedMTU = 16300`
- 同一连接的文件必须经 `queueConnSend()` 串行发送；分片可能是 ArrayBuffer / Uint8Array
- `PROTOCOL = 5`，新页面与参考样本的页面不混连；线上 `index.html` 需整份替换
- 入口页三视图用 CSS grid 同格叠放 + `visibility` 切换，**不能改 `display`**，否则卡片尺寸会跳
- 运行 exe 只启动服务，**不会**自动导出页面；打包必须带 `--add-data "web;web"`
- 纯外网房间界面零局域网信息；局域网信息卡只在开启且程序就绪时显示

## 已知边界

- 访客点过下载、已保存到本机「下载」目录的文件，网页无法代为删除；销毁清的是各端页面与内存中的数据
- 房间创建依赖 PeerJS 公共信令服务器在线；只内置公共 STUN、无 TURN，对称 NAT 下可能打不通
  （可在房间「网络」弹窗里配置自己的 TURN）
- `http://192.168.x.x` 页面不能发起屏幕共享（浏览器安全限制）
- 局域网走明文 HTTP，仅限可信网络使用
