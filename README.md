# 数据传输

绿色免安装的单文件工具。双击运行，同一局域网内任意多台设备互传文字、文件和桌面；不在同一网络时走 WebRTC 点对点直传。

> **下载**：[数据传输.exe](数据传输.exe)（9.4 MB，免安装，双击即用）
>
> **在线版**：<https://zvzqvqdvd.github.io/data-transmission/> —— 入口页也有「下载 Windows 程序」按钮；本机没装程序就点「创建房间」时，页面会直接把下载按钮摆出来。
>
> 本仓库是**完整项目源码**，clone 下来就能改、能打包、能发布。

## 能做什么

- **多人房间**：房主开房，外网和局域网都能进，没有人数上限，所有人看同一份聊天记录
- **文字聊天**：微信风格，消息带时间与发送者编号，2 秒内自动同步
- **文件互传**：多选上传、逐字节无损；同名文件自动加序号不会覆盖；文件只存房主设备，其他设备点卡片按需下载
- **发送队列**：逐项显示 等待 / 传输中（百分比 + 实时速度 + 剩余时间）/ 完成 / 失败
- **拖拽与粘贴**：文件拖进窗口即入队，截图 Ctrl+V 直接发
- **桌面共享**：一键把屏幕推给房间里所有人，1080p / 30fps / 6 Mbps，可带系统声音，画面就显示在聊天流里。**仅外网设备能看**（局域网不是安全上下文）
- **局域网直连**：同一 WiFi 用 `192.168.x.x:8000` 访问，不绕外网、不耗流量
- **临时房间**：房间码只在本次运行有效。关房主页面、12 小时无通信、点「销毁房间」都会销毁，聊天记录与文件一并删除
- **设备管理（仅房主）**：能看到各通道设备数与匿名编号，其他设备看不到也拿不到
- **完全离线**：把 `index.html` 发给任何设备，浏览器打开就能当访客

## 快速开始

### 房主

1. 双击 `数据传输.exe`，UAC 点「是」放行 8000 端口。控制台窗口保持开着就是服务在跑，关窗口或 Ctrl+C 停止
2. 本机打开 `http://127.0.0.1:8000`，点「创建房间」
3. 等进度走完（检查本机程序 → 创建房间 → 连接外网通道）就进房了，右侧能看到房间号

**启动程序不等于开了房间**——要点「创建房间」才生成房间码。

进房后右侧从上到下：房间卡（房间号点击复制 / 新建房间 / 销毁房间）→ 局域网卡（地址、复制、二维码、设备清单）→ 外网卡（链接、二维码、设备清单）→ 房间说明按钮。**设备数、IP、等待条只给房主看**。

### 其他设备

打开房主给的链接或扫码 → 输入 10 位房间码 → 「连接」。

点连接会**先真连一次**：房间不存在或连不上就停在入口页说明原因，不会让你进一个收不到文件的空页面。连上后界面和房主一样，只是少了房主专属按钮。

**刷新不用重输房间码**：加入过的房间记在本标签页里，刷新自动填码静默重连；正常退出或房间销毁时记录即清。

### 同一 WiFi 的捷径

房主页面顶部写着 `192.168.1.5:8000`：

- 「复制访问地址」→ 对方浏览器打开，**要输房间码**
- 「二维码」→ 扫码免输直接进，码里带着房间码

前提：同一网段（路由器的「访客网络」或 AP 隔离会挡住）；`http://192.168.x.x` 不是安全上下文，**不能发起桌面共享**。

### 三种身份对比

| | 创建房间 | 外网加入 | 局域网直连 |
|---|---|---|---|
| 前提 | 本机程序已启动 | 无，任何设备都行 | 程序已启动 + 同 WiFi |
| 输房间码 | — | 要 | 要（记一次） |
| 文件存哪 | 房主 `数据/房间/<码>/接收文件/` | 点卡片下载到浏览器下载目录 | 房主磁盘 |
| 发起桌面共享 | 能 | 能（手机浏览器不行） | 不能 |
| 观看桌面共享 | 能 | 能 | 不能 |
| 刷新后 | 记录还在 | 自动连回 | 记录还在 |

## 文件传输

所有文件一视同仁——**图片不单独分类，不做任何在线预览**。聊天里就是一张卡（扩展名 + 文件名 + 大小），**点卡片本体就下载**。卡片上不放下载图标：那个字符在手机 / 电脑 / iOS 上渲染不一致。

- **房主 / 局域网设备**：走本机 HTTP 直接落盘，最快
- **外网访客**：从房主 P2P 分片拉取，卡片下方显示进度条
- **发送队列**：完成的条目自动清掉，失败的留着可 ↻ 重试

不做预览是刻意的：预览得先把整个文件拉过来，流量和等待都白花；缩略图在各家 WebView 上的渲染差异也是死结。

## 桌面共享

点输入框右边的显示器图标，选窗口或整个屏幕，画面作为一张视频卡出现在聊天流最上方（16:9，手机端拉到整行宽），点卡片进全屏。

- **后加入的人自动看直播**，不用点任何按钮
- **停止后同一张卡原地变灰**（起止时间 + 时长 +「画面不保存回放」标注），历史始终只有一条
- 手机只能看不能发起——浏览器没有实现屏幕采集
- 自动播放被系统拦下时卡上出现「▶ 点击播放共享画面」，点一下用手势重播
- 只有安全上下文（https / `127.0.0.1`）能发起

## 数据存在哪、留多久

```
数据/房间/<房间码>/
├── 聊天记录.json     这个房间的全部消息（文本 + 文件条目）
└── 接收文件/         这个房间收到的文件
```

- 一个房间一个文件夹，**删掉文件夹就等于删掉那个房间**
- 房间销毁（手动 / 关房主页面 / 12 小时无通信）时整个文件夹当场删除，**不可恢复**
- 程序退出时看门狗会清掉本次运行遗留的房间文件夹
- 想留东西，请在销毁前把 `接收文件/` 里的文件拷走

程序运行时只依赖 `client_url.txt`（在线地址）和 `数据/`，缺了会自动创建。**房间码只存在内存里**，关掉程序房间就结束。

## 从源码运行与打包

```bash
python 数据传输.py                   # 直接跑，改完存盘重开即可看效果
python 数据传输.py --export-page     # 导出单文件页面到 data-transmission/index.html
```

**启动程序不会导出页面**（2026-11-11 起）：跑服务就是跑服务，发布页只由上面那条 `--export-page` 生成。好处是正在跑的旧 exe 重启时，不会把它内嵌的旧页面覆盖回 `data-transmission/index.html`。

`web/` 是**编译期依赖**，必须和 `数据传输.py` 同级。打包 exe：

```
python -m PyInstaller --onefile --clean --noconfirm --add-data "<项目绝对路径>/web;web" --distpath . --workpath "%TEMP%\dt_build" --specpath "%TEMP%\dt_build" --name 数据传输 数据传输.py
```

`--add-data` 必须用绝对路径（`--specpath` 会改变相对路径的基准）。漏了它，exe 只有几 MB 且启动就报「缺少页面源文件」。打包前最好关掉正在跑的旧程序，否则 exe 被占用写不进去。

## 仓库结构

main 分支根目录既是 GitHub Pages 的站点根目录，也是源码根目录：

| 路径 | 作用 |
|---|---|
| `index.html` | Pages 入口（`data-transmission/index.html` 的副本，单文件、零外链） |
| `数据传输.exe` | 主程序，入口页的下载按钮指向它 |
| `数据传输.py` | 后端源码（服务端、上传、鉴权、房间码、页面导出） |
| `web/` | 界面源码六文件：`page.html` / `app.css` / `app.js` / `room.js` / `gate.js` / `vendor.js` |
| `client_url.txt` | 在线地址，决定邀请链接用哪个域名 |
| `.gitignore` `.gitattributes` `.nojekyll` | 排除产物、禁用换行转换、Pages 配置 |

**不进仓库**：`build/` `dist/`（PyInstaller 中间产物，一条命令重建）、`数据/`（房间记录与用户文件）。

**页面为什么有两份**：`web/` 是源码，根目录 `index.html` 是 `build_page()` 把六个文件合并出来的产物。Pages 只能发布静态文件，所以产物必须躺在站点根目录；源码留着是为了可改、可复现。

三个业务 JS 是**源码层面的拆分**：`build_page()` 按 `app.js → room.js → gate.js` 拼进同一个 `<script>`、共用一个作用域，导出后仍是单文件，访客端零外部请求。

## 发布更新

- 主地址 `https://zvzqvqdvd.github.io/data-transmission/`，自定义域名 `https://zvzqvqdvd.top/`（同一份文件、同一目录）
- 改了界面 → 重新导出，拖 `index.html` + 改过的 `web/` 文件
- 改了后端 → 拖 `数据传输.py`（顺带重新导出一次，页面版本号会变）
- 只重新打包 → 拖 `数据传输.exe`（下载链接是运行时拼的，不用动页面）
- exe 是**二进制，只能网页拖拽上传**（在线编辑器会损坏文件），9.4 MB 远低于 25 MB 上限

导出机制：读取 `web/` 六个文件，把 CSS、`vendor.js` 和按顺序拼接的三段业务 JS 内联进 `page.html`，写到 `data-transmission/index.html`（目录不在会自动建）。**启动程序不会导出**，要手动跑 `--export-page`。**不要直接编辑这个文件**。

**对版**：进房点「🕒 房间说明」，底部「页面版本」应为 **`5ad34fab18`**（对应 `index.html` 351,067 字节 / md5 `67247a77`）。线上对不上就是没覆盖上传或被缓存了。

邀请链接和二维码带 `?v=<页面指纹>`，页面一变指纹就变，用来穿透手机浏览器的顽固缓存——程序更新后让访客用**新**二维码进房。

## 已知限制

- 只内置公共 STUN，**没有 TURN 中继**；双方都在对称 NAT 下可能打不通（右上角 🌐 可自己加一台 TURN）
- 微信 / QQ 内置浏览器通常不支持 WebRTC，请用系统浏览器打开
- 房主是外网设备之间**唯一的中继**：房主关掉页面，外网设备之间就收不到彼此消息（局域网设备不受影响）
- 外网传大文件速度取决于双方带宽，下载期间房主要保持页面打开
- 访客只拿到最近 200 条历史，更早的只存在房主磁盘上
- 桌面共享多人同时看很吃上行：房主给每台外网设备各推一路流
- 局域网 `http://<IP>:8000` 是明文 HTTP，不适合传敏感数据
- 管理员密码默认 `admin`；**跑程序那台机器本身就算管理员，不用输密码**，局域网其他设备看不到管理入口
- 没有「踢人」：想一次清空就「新建房间」或「销毁房间」，房间码一换旧链接立刻失效

## 可选配置

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| `LANSHARE_ADMIN_PASSWORD` | `admin` | 管理员密码，用默认值时启动会打印警告 |
| `LANSHARE_MAX_FILE_SIZE` | 4 GiB | 单文件上传上限（字节） |
| `LANSHARE_CLIENT_URL` | 读 `client_url.txt` | 覆盖在线页地址 |

## 改代码前必看的硬约束

- `CHUNK_SIZE` 必须**小于** PeerJS 的 `chunkedMTU`（16300），现在是 15000。一旦超过，PeerJS 会把每片再拆成两条消息、接收端用 Blob 异步重组，最后一片常比 `FILE_END` 晚一步交上来，整包被判不完整丢弃——表现就是「小文件偶尔能过、手机端传什么都不完整」
- `FILE_END` 字节不足时**不立刻丢弃**，给 2.5 秒宽限等重组补齐（`waitRecvComplete`），真缺片才 `dropRecv`
- 分片可能以 **Blob** 形式到达（微信 X5 / 部分安卓 WebView），必须走 `chunkChain` 异步读成 ArrayBuffer，不能当 null 丢掉
- 房主发文件**必须按连接串行**（`queueConnSend`）：一条连接只有一个接收缓冲，两路并行会让分片互相穿插
- 下载看门狗按**有没有字节在动**判超时（连续 60s 无新数据才算卡住），不是按「发起多久」

## 验证

协议与转发逻辑用 jsdom 回归（假 Peer + 假后端）；创建房间、按钮显隐、重连退避、手机端共享播放、发送队列、房间生命周期等用无头 Chrome + CDP 打桩实测；文件按需下载跑过独立端口的真实链路（房主上传 → 访客收卡 → 点击 → 分片下载完成）。P2P 分片与桌面共享的媒体通道，建议多台真实设备再验一次。
