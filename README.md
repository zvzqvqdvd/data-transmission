# 数据传输

![platform](https://img.shields.io/badge/platform-Windows%2010%20%7C%2011-0078D4)
![size](https://img.shields.io/badge/size-9.0%20MB-07C160)
![dependencies](https://img.shields.io/badge/dependencies-none-07C160)

> **主页**：<https://zvzqvqdvd.github.io/data-transmission/>

打开主页就能用的互传工具：同一 WiFi 下任意多台设备加入同一个房间，互传文字、文件和桌面；不在同一网络时自动走 WebRTC 点对点直传。**不装任何软件也能建房**，需要局域网能力时才下载一个小程序。

- **主页是唯一入口**：创建房间、加入房间都是这一个网址；**外网设备也只有这一条路进来**
- **创建房间时二选一**：`网页直连`（WebRTC P2P，纯网页，零下载，文件只在房主浏览器里）／`局域网`（需本机跑 `数据传输.exe`，文件落盘，同一 WiFi 直连；**外网默认关着**，房主在外网直连卡的「外网加入」开关上自己拨开，外网才凭链接进得来）
- **加入房间**永远不用装任何东西，手机、平板、Mac、Linux 打开网页就行
- 不租服务器、不注册账号：**聊天记录一律不落盘**；文件在纯网页房间存房主浏览器，在局域网房间存房主磁盘，房间销毁即删除

## 快速开始

**都从主页开始**：<https://zvzqvqdvd.github.io/data-transmission/>。创建与加入是同一个网址。

**这个工具有三个地址，各管一头**：

| | 主地址（在线页） | 本地地址（房主本机） | 局域网地址（同一 WiFi） |
|---|---|---|---|
| 网址 | <https://zvzqvqdvd.github.io/data-transmission/> | <http://127.0.0.1:8000> | <http://192.168.x.x:8000>（IP 因路由器而异） |
| 存在于 | GitHub Pages，任何人都能打开 | 房主运行 exe 后，只在**房主自己电脑**上 | 同一个服务，同一 WiFi 内的设备都能打开 |
| 是什么 | 静态网页，所有设备的统一入口 | 房主本机的后台服务 | 本地服务的局域网入口（同一后台） |
| 能做什么 | 创建纯网页房间、加入房间、收文件、看桌面共享 | 生成房间号、保存接收的文件（聊天记录只在内存）、配合 WebRTC 与各设备直连 | 与本地地址相同 |
| 谁在用 | 所有设备（含房主自己） | 只有房主本机 | 同一 WiFi 下的手机 / 电脑等，外网打不开 |

**三者的关系**：本地地址和局域网地址是**同一个后台服务**的两个入口——房主本机用回环地址，同一 WiFi 的设备用局域网地址，都连到房主 exe 上的服务；主地址是门面，管所有设备的入口。**只有在创建时选了「局域网」**，网页才会去跨域访问本机服务的 <http://127.0.0.1:8000>（程序已为这类回环请求配好 CORS，Chrome / Edge 允许），让页面能驱动本地服务干活。关掉 exe 后主地址仍能打开、也仍能创建纯网页房间和加入别人的房间；局域网 / 本地地址则随程序关闭一起失效。

### 一、创建房间（发文件的人）

1. 打开主页，点「创建房间」，再选一种：`网页直连`（WebRTC P2P，零下载，有网就能进）／`局域网`（文件落本机磁盘，同一 WiFi 直连，外网凭链接也能进）
2. 选「局域网」时，本机没跑程序就会切到下载屏：下载 [数据传输.exe](数据传输.exe)、双击运行，UAC 点「是」放行 8000 端口，再回卡片点「重新创建」
3. 等进度走完（纯网页：准备房间 → 直连通道；局域网：检查程序 → 创建房间 → 直连通道），右侧出现 10 位房间号

把房间号、二维码或链接发给对方就行。**控制台窗口保持开着就是服务在跑**，关窗口或 Ctrl+C 停止。

> 纯网页房间：最多 6 人；容量按建房时浏览器的可用空间现算（总量 = 可用 × 80%，单文件 = 总量的 10%），探测不到配额就禁止上传；聊天记录与文件在房主浏览器里（IndexedDB），刷新可恢复，关页面即结束。

> 启动程序 ≠ 开了房间。程序只是起了本地服务，要点「创建房间」才会生成房间码。

若房主本机浏览器拦了上面的跨域请求，直接打开程序控制台里提示的本地地址操作即可。

### 二、加入房间（其他设备）

打开主页，或房主给的链接 / 扫二维码 → 输入 10 位房间码 → 「连接」。

**外网设备只有这一条路**：打开这份在线页面（主页、房主发的邀请链接，或房主把 `index.html` 直接发给你），由页面通过 WebRTC 点对点直连房主——房主的本机服务地址和局域网地址，外网都是打不开的。

手机、平板、Mac 都行，**不用装任何东西**。点「连接」会先真连一次：房间不存在或连不上就停在入口页说明原因，不会让你进一个收不到文件的空页面。刷新也不用重输房间码——加入过的房间记在本标签页里，刷新自动填码静默重连。

> 一句话记住：**创建房间需要房主本机已运行程序；加入房间不需要，任何设备打开主页就能加。**

### 三种进入方式

| | 创建房间 | 外网加入 | 局域网直连 |
|---|---|---|---|
| 从哪进 | 主页 →「创建房间」 | **主页 / 邀请链接（唯一途径）** | `http://192.168.x.x:8000` |
| 前提 | 本机程序已启动 | 无，任何设备都行 | 程序已启动 + 同 WiFi |
| 输房间码 | — | 要 | 要（记一次） |
| 文件存哪 | 房主 `数据/房间/<码>/接收文件/` | 点下载按钮存到浏览器下载目录 | 房主磁盘 |
| 发起桌面共享 | 能 | 能（手机浏览器不行） | 不能 |
| 观看桌面共享 | 能 | 能 | 不能 |
| 刷新后 | 记录还在 | 自动连回 | 记录还在 |

## 功能

| 功能 | 说明 |
|---|---|
| 纯网页建房 | 创建时选 `WebRTC P2P`，打开主页就能建房，零下载；聊天记录与文件只在房主浏览器里 |
| 多人房间 | 房主开房，外网和局域网都能进，**最多 6 人（房主 + 5 台设备）**，所有人看同一份聊天记录 |
| 文字聊天 | 微信风格，消息带时间与发送者编号；长轮询推送，局域网通常几十毫秒上屏 |
| 文件互传 | 多选 / 拖拽 / 粘贴上传，逐字节无损；同名文件自动加序号，不覆盖 |
| 发送队列 | 逐项显示 等待 / 传输中（百分比 + 实时速度 + 剩余时间）/ 完成 / 失败 |
| 桌面共享 | 一键把屏幕推给房间里所有人，1080p / 30fps / 6 Mbps，可带系统声音 |
| 局域网直连 | 同一 WiFi 用 `192.168.x.x:8000` 访问，不绕外网、不耗流量 |
| 临时房间 | 房间码只在本次会话有效；30 分钟无通信、房主关闭或离线即销毁 |
| 在线状态 | 房主每 5 秒体检一次连接，掉线设备在十几秒内自动从清单消失 |
| 完全离线 | 把主页这份 `index.html` 发给任何设备（同一份页面），浏览器打开就能当访客 |

## 使用说明

### 房主的侧栏

进房后右侧竖排，从上到下**按房间类型挂不同的卡**（建房时二选一决定了挂哪几张，局域网房间里还能再拨一次外网开关）：

| 房间类型 | 卡片（自上而下） |
| --- | --- |
| **网页直连房间**（WebRTC P2P） | 房间卡（徽标 `网页直连`、房间号、60 分钟倒计时、销毁）→ **存储空间卡**（已用 / 单文件上限 / 进度条）→ **外网直连卡**（邀请地址、复制访问地址、二维码、设备清单）。这张卡没有开关——它本身就是外网通道 |
| **局域网房间**（刚建好，外网加入默认关） | 房间卡（徽标 `局域网`）→ **局域网卡**（`192.168.x.x:8000`、复制访问地址、二维码、设备清单）→ **外网直连卡收起**：虚线描边、灰底，标题行右侧一个灰色「外网加入」开关，下面一行「已关闭 · 链接与二维码已失效，只有同一 WiFi 的设备能加入」 |
| **局域网房间**（外网加入拨开） | 房间卡 → 局域网卡 → **外网直连卡**：开关变绿，邀请地址、复制访问地址、二维码、设备清单全部出现 |

两种房间都**没有存储空间卡以外的容量概念**：局域网房间的文件直接落这台电脑的磁盘，房间卡上写「在线 N / 6 人」和「空闲剩余 mm:ss」，不占浏览器配额。

房间卡顶部的徽标写着这台电脑开的是哪种房间（`网页直连` / `局域网`），手机上也保留——窄屏只是把「房间」两个字省了。

要点：**外网直连卡两种房间都有**——网页直连房间只是没有「局域网卡」，不是没有地址卡；局域网房间靠卡上的开关决定这扇门开不开。三张通道卡（局域网 / 外网直连 / 访客连接）都是同一套结构：一行通道名 + 可点击复制的地址 +「复制访问地址 / 二维码」+ 设备清单。

**「外网加入」开关怎么工作**：局域网房间建好时是**关着**的——不注册房主 Peer，一个字节都不碰信令服务器，邀请地址和二维码也还不存在。房主拨开的那一刻才注册 `pc-<房间码>`，地址、二维码、设备清单同时出现；拨回去就当场失效。关掉时正在连的外网设备会先收到一条 `P2P_OFF`，退回起始页并写明「房主已关闭外网加入」；之后再来敲门的人在握手阶段就被回绝，入口页几秒内给出同一句提示，不会一直停在「正在连接」。房间码始终不变，局域网走 HTTP，开关对同一 WiFi 的设备完全无影响。想让房主这侧也彻底不碰外网，销毁房间即可。

「房间说明」在顶栏——手机上它没地方摆，塞进卡片条里要往右滑才看得见，不合理。

**设备数、IP、等待条只给房主看。**

### 同一 WiFi 的捷径（更快）

房主页面顶部写着 `192.168.1.5:8000`：

- 「复制访问地址」→ 对方浏览器打开，**要输房间码**
- 「二维码」→ 扫码免输直接进，码里带着房间码

走这条不绕外网、不耗流量，大文件快很多。前提是同一网段（路由器的「访客网络」或 AP 隔离会挡住）。`http://192.168.x.x` 不是安全上下文，**不能发起桌面共享**。

### 窄屏与手机

≤1099px 不再横向滑动：卡片纵向铺开、占满整行，一眼看全。≤640px 时局域网 / 外网两张卡默认收起成一行（标签 + 在线设备数 + 展开箭头），点一下才展开地址、复制、二维码和成员清单——房间号始终可见，因为别人要靠它加入。

### 文件传输

所有文件一视同仁——**图片不单独分类，不做任何在线预览**。聊天里就是一张卡（扩展名 + 文件名 + 大小），只有卡片右侧那个下载按钮能下载，点卡片本体不响应（手机上误触太容易）。

- **房主 / 局域网设备**：走本机 HTTP 直接落盘，最快
- **外网访客**：从房主 P2P 分片拉取，卡片下方显示进度条
- **发送队列**：完成的条目自动清掉，失败的留着可 ↻ 重试

不做预览是刻意的：预览得先把整个文件拉过来，流量和等待都白花；缩略图在各家 WebView 上的渲染差异也是死结。

### 桌面共享

点输入框右边的显示器图标，选窗口或整个屏幕，画面作为一张视频卡出现在聊天流最上方（16:9，手机端拉到整行宽），点卡片进全屏。

- **后加入的人自动看直播**，不用点任何按钮
- **停止后同一张卡原地变灰**（起止时间 + 时长 +「画面不保存回放」标注），历史始终只有一条
- 手机只能看不能发起——浏览器没有实现屏幕采集
- 自动播放被系统拦下时卡上出现「▶ 点击播放共享画面」，点一下用手势重播
- 只有安全上下文（https / `127.0.0.1`）能发起

### 数据存在哪、留多久

```
数据/房间/<房间码>/
└── 接收文件/         这个房间收到的文件
```

- **聊天记录不落盘**：只在程序内存里活着，程序退出或房间销毁即消失，磁盘上不会生成任何聊天记录文件
- 一个房间一个文件夹，**删掉文件夹就等于删掉那个房间**
- 房间销毁（手动 / 关房主页面 / 房主离线 / 30 分钟无通信）时整个文件夹当场删除，**不可恢复**
- 程序退出时看门狗会清掉本次运行遗留的房间文件夹
- 想留东西，请在销毁前把 `接收文件/` 里的文件拷走

程序运行时只依赖 `client_url.txt`（主页地址）和 `数据/`，缺了会自动创建。**房间码只存在内存里**，关掉程序房间就结束。纯网页房间没有磁盘：聊天记录与文件在房主浏览器的 IndexedDB 里，房间结束即清除。

## 常见问题

### Windows 提示「已保护你的电脑」

下载后首次运行，可能先后遇到两种提示：

| 提示 | 出现在哪 | 怎么过 |
|---|---|---|
| 「通常不会下载 数据传输.exe」 | 浏览器下载栏 | 点右侧「…」→「保留」 |
| 「Windows 已保护你的电脑 / 无法验证此文件是否安全」 | 双击运行时 | 点「更多信息」→「仍要运行」 |

第二个弹窗里，「**更多信息**」是一行可以点的链接，很多人没注意到就关掉了——点开之后才有「仍要运行」按钮。

**为什么每个新版本都会被拦一次**

SmartScreen 不看代码，只查两件事：这个文件有没有数字签名、这个文件被多少人下载过。

本项目是个人维护的免安装小工具，没有代码签名证书；而且每次发版都是一个**全新的文件哈希**，上一个版本攒的下载量不会继承给新版本。所以每个新版本都从「零声誉」重新开始，第一个运行它的人必然被拦。

**这不是「检测到病毒」，是「微软不认识这个文件」。**

彻底消除只有三条路：

- **买代码签名证书**：需要企业资质。OV 约 ¥1200–4400/年，EV 约 ¥2500–6600/年。注意 2024 年起微软已取消 EV 免 SmartScreen 的特权，两者都要重新积累声誉
- **上架微软商店**：MSIX 由微软重新签名，用户端零提示
- **开源项目免费签名**：[SignPath Foundation](https://signpath.org/)，需要 OSI 认可的开源许可（本仓库目前未附 `LICENSE` 文件）

个人自用和小范围分发，走上面「保留 + 仍要运行」那两步就够了。

嫌每次点「仍要运行」麻烦：右键 exe → 属性 → 勾「解除锁定」→ 确定，可去掉下载标记。

### 对方打不开链接

微信 / QQ 内置浏览器通常不支持 WebRTC，请让对方点右上角「在浏览器打开」，或把链接复制到系统浏览器。

### 外网连不上

只内置公共 STUN，**没有 TURN 中继**。双方都在对称 NAT（常见于移动网络、严格企业网络）下可能打不通。此时改用同一 WiFi 直连，或点右上角的网络图标加一台自己的 TURN 服务器（配置只存在这台设备的浏览器里，不上传）。

### 怎么确认文件没被改过

每个版本的 SHA256 记在下面的「版本与校验」一节，下载后比对：

```cmd
certutil -hashfile 数据传输.exe SHA256
```

## 已知限制

- 只内置公共 STUN，**没有 TURN 中继**；对称 NAT 下可能打不通
- **纯网页房间没有本地服务**：不支持局域网设备加入；聊天记录与文件存在房主浏览器里，清理浏览器数据会一并丢失；容量按建房时浏览器的可用空间算（总量 = 可用 × 80%，单文件 = 总量 × 10%），探测不到配额就禁止上传
- 房主是外网设备之间**唯一的中继**：房主关掉页面，外网设备之间就收不到彼此消息（局域网设备不受影响）
- 外网传大文件速度取决于双方带宽，下载期间房主要保持页面打开
- 外网访客只拿到最近 200 条历史，更早的不会转发
- 桌面共享多人同时看很吃上行：房主给每台外网设备各推一路流
- 局域网 `http://<IP>:8000` 是明文 HTTP，不适合传敏感数据
- **没有管理面板**：房间里谁在线，看右侧通道卡上的设备清单就够了；不做踢人、不改别人的记录
- 没有「踢人」：想一次清空就「销毁房间」再重新创建，房间码一换旧链接立刻失效

## 开发者

### 从源码运行

需要 Python 3.7+，**只用标准库，没有任何第三方依赖**。

```bash
python 数据传输.py                   # 直接跑，改完存盘重开即可看效果
python 数据传输.py --export-page     # 重新生成根目录的单文件页面 index.html
python tests/smoke.py                # 后端冒烟（17 项，含导出页面逐字比对）
node tests/cloud_store.test.mjs      # 云房间仓库（13 项，IndexedDB 用内存替代）
```

`web/` 是**编译期依赖**，必须和 `数据传输.py` 同级。

**启动程序不会导出页面**：跑服务就是跑服务，页面只由 `--export-page` 生成，写到根目录 `index.html` 一处。好处是正在跑的旧 exe 重启时，不会把它内嵌的旧页面覆盖回磁盘。

### 打包 exe

```
rm -rf build dist
python -m PyInstaller --onefile --noupx --noconfirm \
  --version-file "<项目绝对路径>/version_info.txt" \
  --add-data "<项目绝对路径>/web;web" \
  --distpath dist --workpath build --specpath build 数据传输.py
```

<details>
<summary>四条容易踩的坑（点开）</summary>

- `--add-data` **和** `--version-file` 都必须用绝对路径。`--specpath build` 会把相对路径的基准改到 `build/`，相对写的版本文件直接 `FileNotFoundError`。
- **改了 `web/` 一定要先 `rm -rf build dist`**。增量构建会复用上次的 `EXE-00.toc` 和 PKG，`--add-data` 目录里的改动不会被重新收进去——表现是打包只用 3 秒、导出页面还报「已是最新」，exe 里其实是旧界面。
- `--version-file` 把产品名、版本、用途写进 exe 属性，**别省**：没有版本信息时 Windows 会把它当「来历不明的打包程序」，SmartScreen 和杀软更容易拦。
- `--noupx` 关掉 UPX 压缩。UPX 压过的 exe 是杀软误报的高发区，只省几 MB，不值。

打包前记得关掉正在跑的旧程序，否则 exe 被占用写不进去。

</details>

<details>
<summary>打完怎么自检（点开）</summary>

把新 exe 拷进一个空目录跑 `数据传输.exe --export-page`，生成的 `index.html` 应与项目根目录那份除 `CLIENT_URL` 外**逐字一致**；不一致就说明 exe 里的界面不是最新的。

</details>

### 仓库结构

main 分支根目录既是 GitHub Pages 的站点根目录，也是源码根目录：

| 路径 | 作用 |
|---|---|
| `index.html` | **主页本体**，Pages 入口，也是 `--export-page` 的产物（单文件、零外链） |
| `数据传输.exe` | 房主本机的服务程序，仅创建房间时需要；「创建房间失败」那一屏的下载按钮指向它 |
| `数据传输.py` | 后端源码（服务端、上传、鉴权、房间码、页面导出；v2 起聊天记录纯内存、30 分钟销毁） |
| `web/` | 界面源码八文件：`page.html` / `app.css` / `app.js` / `cloud.js` / `store.js` / `room.js` / `gate.js` / `vendor.js` |
| `tests/` | 最小冒烟：`smoke.py`（后端接口 + 页面逐字比对）、`cloud_store.test.mjs`（云仓库） |
| `client_url.txt` | 主页地址，决定邀请链接用哪个域名 |
| `version_info.txt` | exe 的版本信息资源 |
| `.gitignore` `.gitattributes` `.nojekyll` | 排除产物、禁用换行转换、Pages 配置 |

**不进仓库**：`build/` `dist/`（PyInstaller 中间产物，一条命令重建）、`数据/`（房间记录与用户文件）。

**源码与产物的关系**：`web/` 是源码，根目录 `index.html` 是 `build_page()` 把六个文件合并出来的产物。Pages 只能发布静态文件，所以产物必须躺在站点根目录；源码留着是为了可改、可复现。三个业务 JS 按 `app.js → room.js → gate.js` 拼进同一个 `<script>`、共用一个作用域，导出后仍是单文件，访客端零外部请求。**不要直接编辑 `index.html`**——改了下次导出就被覆盖。

### 发布更新

主页地址 `https://zvzqvqdvd.github.io/data-transmission/`。

| 改了什么 | 要上传 |
|---|---|
| 界面 | 重新导出后传 `index.html` + 改过的 `web/` 文件 |
| 后端 | 传 `数据传输.py` 和重新打包的 `数据传输.exe`，顺带重新导出一次（页面指纹会变） |
| 只重新打包 | 传 `数据传输.exe`（下载链接是运行时拼的，页面不用动） |

exe 是**二进制，只能网页拖拽上传**，在线编辑器会损坏文件。9.0 MB 远低于 25 MB 上限。

邀请链接和二维码带 `?v=<页面指纹>`，页面一变指纹就变，用来穿透手机浏览器的顽固缓存——程序更新后让访客用**新**二维码进房。

<details>
<summary>给改代码的人：五条硬约束（点开）</summary>

- `CHUNK_SIZE` 必须**小于** PeerJS 的 `chunkedMTU`（16300），现在是 15000。一旦超过，PeerJS 会把每片再拆成两条消息、接收端用 Blob 异步重组，最后一片常比 `FILE_END` 晚一步交上来，整包被判不完整丢弃——表现就是「小文件偶尔能过、手机端传什么都不完整」
- `FILE_END` 字节不足时**不立刻丢弃**，给 2.5 秒宽限等重组补齐（`waitRecvComplete`），真缺片才 `dropRecv`
- 分片可能以 **Blob** 形式到达（微信 X5 / 部分安卓 WebView），必须走 `chunkChain` 异步读成 ArrayBuffer，不能当 null 丢掉
- 房主发文件**必须按连接串行**（`queueConnSend`）：一条连接只有一个接收缓冲，两路并行会让分片互相穿插
- 下载看门狗按**有没有字节在动**判超时（连续 60s 无新数据才算卡住），不是按「发起多久」

</details>

<details>
<summary>入口页的几条设计约定（点开）</summary>

- 入口页**不摆下载入口**。本机没装或没启动程序时点「创建房间」，卡片会就地切到下载引导那一屏（和「输入房间号」同一种切换，不弹窗、不遮页面），点「返回」原样退回
- 那一屏的下载按钮自带缓存进度，缓存满了才落盘到「下载」；程序大小是进这一屏时现取的，不写死
- 卡片是**固定尺寸**的：换屏、点按钮、冒提示，宽高都不变。三块视图用 CSS grid 同格叠放，隐藏切 `visibility` 不切 `display`
- 响应式按**三条轴**分开写，互不覆盖：宽度断点只管左右内边距与字号，高度断点只管上下节奏（矮屏时 logo、副标题按档收起），`hover:none` 只管关掉悬停位移。三者用的都是 `padding-top` / `padding-left` 这类单边属性，所以 320×568 这种「又窄又矮」的屏能同时吃到两种收法
- 居中靠 `.gate-card { margin:auto }` 而不是 `align-items:center`：横屏手机上卡片比视口高，`center` 会把顶部推到滚动区之外，`auto` 在空间不足时自动归零、从顶部开始
- 动画只动 `opacity` 与 `transform`，不碰宽高，全部带 `prefers-reduced-motion` 兜底
- 下载按钮右侧的大小徽标宽度固定，网络慢时先显示「…」，探到真值再换成「8.8 MB」，按钮文字一点不挪

</details>

> **2.0.16（当前版本，页面 + exe）**：局域网房间的外网改成「默认关、房主自己开」，关闭时把外网设备请回起始页。
> ① **默认关**：点「局域网」建房不再顺手注册房主 Peer——不碰信令服务器，邀请地址和二维码也不生成，开出来就是一间只有同一 WiFi 能进的房间。要用外网，房主在外网直连卡的「外网加入」开关上拨一下，那一瞬间才注册 `pc-<房间码>`，地址与二维码同时出现。
> ② **关掉时把已经连着的外网设备请出去**：以前只是静默断开，访客那边当成掉线，自动重连回来又被拒，界面一直挂在「正在重新连接」，人既没被踢回起始页也不知道为什么。现在先给每台在线的外网设备发一条 `P2P_OFF`，留 220ms 让它真的发出去，再收连接；访客收到就退回起始页，并写明「房主已关闭外网加入…」。实测从房主点确认到访客回到起始页 0.3s。
> ③ **关着的时候来敲门，当场回绝**：以前那句提示是在 `connection` 事件里发的，那时数据通道还没 open，`send` 直接丢掉，访客只能干等到超时——表现就是「一直连接中没有任何提示」。现在改成 `open` 之后再发 `P2P_OFF` 再关，入口页的探活也认这条消息，0.6s 就给出结果。
> ④ **文案跟着改**：`peer-unavailable` 不再只说「房间不存在」，而是把三种可能一起讲清（码不对／房间关了／房主关着外网加入），并提示同一 WiFi 可用局域网地址进入。
>
> **2.0.15（历史，页面 + exe）**：修掉「在线页开的局域网房间没有外网开关」。
> ① **现象**：从 GitHub Pages 那份页面（或磁盘上的 `index.html`）点「局域网」创建房间，房间卡正常、局域网卡正常，但外网直连卡一出生就是虚线灰底的「已关闭」，标题行**没有开关**——想拨回去没地方点，这个房间永远只能局域网。
> ② **原因**：`__P2P_ENABLED__` 承担了两个意思——「这份页面能不能当外网房主」和「这份页面是不是局域网设备拿到的」。模板只给 `mode == 'host' and p2p` 写 `true`，于是在线页（guest 模板）恒为 `false`；`gateCreateLan` 拿它算 `needP2P`，在线页就真的按 `p2p=0` 建房，`renderP2PCard` 又拿它决定开关显不显示，两处一起把开关藏了。

> ① **三选一**：入口页去掉「开启局域网访问」开关，点「创建房间」后选 `WebRTC P2P`（纯网页，零下载，文件存房主浏览器）／`局域网`（需本机程序，文件落盘，仅同一 WiFi 可进）／`WebRTC P2P + 局域网`（两种入口都开）。选「局域网」**不再注册 P2P 房主**，外网进不来、界面也不出现任何外网卡片；选择记在房间上（`/api/room/create?p2p=0`，`/api/host` 回传 `p2p`），刷新后原样恢复，不会偷偷把外网通道开回来。选择页的返回改成卡片左上角小箭头，底部不再挂通栏「返回」；选择页多一行 P2P / 局域网对照，建之前就知道差别。
> ② **配额探测失败即禁传**：浏览器报不出可用存储（无痕模式 / 旧内核）时不再退回 500 MB，直接禁用上传并说明「请用最新版浏览器、不要开无痕」，房主与访客两边都拦（房主经 `PEERS` 广播 `nf` 标记）。
> ③ **动态容量**：建房时按浏览器可用配额算容量，总量 = 可用空间 × 80%，单文件 = 总量 × 10%（Chrome 实测 8.0 GB / 819.2 MB），刷新沿用同一份数字。
> ④ 空闲销毁 30 → **60 分钟**，倒计时移到房间卡里「空闲剩余 mm:ss」。
>
> **2.0.6（历史，页面 + exe）**：入口页重做。
> ① **布局**：间距收成一套刻度（26 / 16 / 10 / 13 / 10，自上而下递减），视觉重心压在「创建房间」；「开启局域网访问」那行去掉描边、灰底压到 2.8%，不再跟按钮抢视线；免责声明字号与勾选框各收一档；页脚两行文案缩短（「创建房间无需安装」「手机电脑都能加入」）。图标从全角 `＋` `→` 换成 SVG，跟按钮同色、粗细一致。
> ② **动画**：卡片入场从「整块淡入」改成子元素逐级上浮（logo 弹入 + 标题/副标题/按钮/声明/页脚依次延迟 0~220ms）；视图切换按方向走——前进（选择 → 输入房号 / 下载引导）从右侧滑入、旧页向左退，后退反之，方向由 `gateView()` 写在 `data-nav` 上；按钮 hover 抬起 1px 并落影、图标放大 7%，按下回弹；开关滑块改成 0.28s 带回弹的曲线。
> ③ **响应式**：三条轴分开处理——宽度（≤400 收内边距、≤340 收字号与图标）、高度（≤700 压扁纵向节奏、≤480 收起 logo 与副标题）、触屏（`hover:none` 关掉 hover 位移，避免点完留下悬停态）。四边让出 `env(safe-area-inset-*)` 给刘海与手势条；居中改用 `.gate-card { margin:auto }`，横屏手机卡片高于视口时从顶部开始可滚动，不会被 `align-items:center` 顶到看不见。
>
> **2.0.5（历史，页面 + exe）**：下载不再自动写盘。下完停在新的一态「**下载完成 · 点击保存**」（实心绿 + 软盘图标，右侧徽标显示大小），点一下才真的存到下载目录，之后变成「已保存 9.0 MB / 完成」。好处是存不存、什么时候存由用户决定，也不会因为连点存出一堆副本；代价是多一次点击。
>
> **2.0.4（历史，页面 + exe）**：① 下完再点按钮是「再次保存」，不再重新下载——`dlmFinish()` 把 Blob 留在 `DLM.blob` 里，点击直接用这份 Blob，不发网络请求（1.2 秒内连点只算一次）。② 修了一个竞态：`dlmProbeSize()` 的 HEAD 探测是异步的，跨域时要绕一圈，可能比下载本身还慢；它回来时用户往往已经下完，于是把徽标从「完成」改回了旧文件大小，看起来像又变回没下。现在探测只在 idle 状态才写徽标。
>
> **2.0.3（历史，页面 + exe）**：**下载 exe 那一屏**也能暂停了。原来点「下载 Windows 程序」后按钮变成只读进度条，中途想停只能关页面。现在按钮本身就是开关——下载中显示「暂停 · 0.5 MB / 9.0 MB」，点一下变「继续 · 0.5 MB / 9.0 MB」（图标在下载箭头、暂停双竖条、播放三角之间轮换），再点带 `Range: bytes=N-` 从断点接着要，服务器回 206，已下的几 MB 不会白扔。服务器不认 `Range`（回 200 全量）时自动从零重下。
>
> **2.0.2（历史，页面 + exe）**：按设计稿补齐四处细节——① 云房主侧栏新增「房间状态」卡（文件 X/500 MB、单文件上限 100 MB、空闲倒计时每秒走、容量进度条，刷新后倒计时接着走）；② 删除下载页多余的「不装软件，直接用纯网页创建」（有「返回」就够了）；③ 入口页三态之间与进出房间加淡入淡出过渡，卡片尺寸不跳动；④ **房间内**的文件下载改为流式读取，支持暂停与断点续传（局域网模式用 `Range` 真续传，云房间文件在本地 Blob 里，仍是直接保存）。
>
> **2.0.1（历史，仅页面）**：修了云房主点「下载」失效的 bug——`downloadLocal()` 原来用 `<a href>` 原生导航，绕过了 `apiFetch` 接缝，云房间没有后端，请求直接打到页面所在的 GitHub Pages，必然 404（浏览器显示「无法下载 · 没有文件」）。访客走 P2P 拉取不受影响，所以现象是「只有房主不行」。
>
> **2.0.0.0**：v2 改造首发——纯网页房主、入口局域网开关、30 分钟无通信自毁、聊天记录一律不落盘、6 人上限、删除死代码。

> **exe 与页面要成对更新**：新页面配旧 exe 时，点「创建房间」探活到的是老服务（没有 30 分钟销毁、没有 6 人上限），界面会显示新文案但行为是旧的；反过来，旧页面配新 exe 则用不到暂停续传、房间状态卡和下载程序的暂停按钮。

**对版**：点顶栏的「房间说明」图标（文档形状），底部「页面版本」应为上表里的指纹。线上对不上就是没覆盖上传或被缓存了。
