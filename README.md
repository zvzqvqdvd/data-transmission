# 数据传输

![platform](https://img.shields.io/badge/platform-Windows%2010%20%7C%2011-0078D4)
![size](https://img.shields.io/badge/size-9.0%20MB-07C160)
![dependencies](https://img.shields.io/badge/dependencies-none-07C160)

> **主页**：<https://zvzqvqdvd.github.io/data-transmission/>
>
> 在线地址以程序目录的 `client_url.txt` 为准——换域名或换托管时只改这一个文件，刷新页面即生效，不用重新打包。

打开网页就能用的互传工具：多台设备进同一个房间，互传文字、文件和桌面。**加入房间永远不用装东西**；只有需要「文件落本机磁盘 + 同一 WiFi 直连」时，房主才下载一个 9 MB 的小程序。

不注册、不租服务器，聊天记录不落盘，房间结束即清空；房间最多 6 人，60 分钟无通信自动结束。主页是唯一入口——创建、加入、外网友客都从这里进。

**适合**：临时传文件、跨系统传文字、给同一屋子的人投屏。
**不适合**：长期存档、账号体系、严格企业网络（没有 TURN 中继）。

## 快速开始

### 创建房间（发文件的人）

打开[主页](https://zvzqvqdvd.github.io/data-transmission/)，点「创建房间」，二选一：

| 选项 | 谁能进 | 要装东西吗 |
|---|---|---|
| `网页直连` | 有网就能进，可跨外网 | 不用，纯网页 |
| `局域网` | 同一 WiFi 更快，文件落本机磁盘 | 房主本机跑 [数据传输.exe](数据传输.exe) |

选「局域网」而本机没跑程序时，页面会直接切到下载引导：下载、双击运行（UAC 点「是」放行 8000 端口），回来点「重新创建」。进度走完，右侧出现 10 位房间码，把码、链接或二维码发给对方即可。**控制台窗口别关，关了服务就停。**

> **局域网房间的外网默认关**。要对外，房主在侧栏「外网直连」卡上把「外网加入」拨开，地址和二维码那一刻才生成，详见[开关怎么工作](#外网加入开关)。
>
> 网页直连房间：文件与聊天存在房主浏览器的 IndexedDB 里，刷新能恢复，关页面即结束；容量按建房时的可用空间现算。

### 加入房间（其他设备）

打开主页 / 房主发的链接 / 扫二维码 → 输 10 位房间码 → 点「连接」。手机、平板、Mac、Linux 都行，**不用装任何东西**。

连接前会真连一次：房间码不对、房间已结束、房主关着外网加入，都会停在入口页说清原因，不会进一个收不到东西的空房间。刷新直接在房间里恢复，不再先闪一屏起始页；房间真没了才退回入口页。

**外网设备只有主页这一条路**：房主的 `127.0.0.1:8000` 只存在于房主自己电脑上，`192.168.x.x:8000` 只在同一 WiFi 里，外网都打不开。

> 一句话记住：**创建可能需要房主本机跑程序，加入不需要。**

## 侧栏有什么

进房后右侧竖排，按房间类型挂卡：

| 房间 | 卡片（自上而下） |
|---|---|
| 网页直连 | 房间卡（徽标、房间码、60 分钟倒计时、销毁）→ 存储空间卡 → **外网直连卡**（邀请地址 / 二维码 / 设备清单） |
| 局域网（外网关，默认） | 房间卡 → **局域网卡**（`192.168.x.x:8000` / 二维码 / 设备清单）→ 外网直连卡收起：虚线灰底 + 灰色开关 |
| 局域网（外网开） | 同上，但外网直连卡展开：开关变绿，邀请地址、二维码、设备清单全出现 |

- 只有**房主**看得到设备数、IP、倒计时和「外网加入」开关；访客和局域网设备没有这些
- 房间卡徽标写 `网页直连` 或 `局域网`，手机上也保留
- ≤640px 时两张通道卡默认收成一行，点一下才展开

### 「外网加入」开关

只在局域网房主的页面上出现，默认关：

- **关**：不注册 Peer、不碰信令服务器、不生成邀请地址，只有同一 WiFi 能进
- **开**：那一刻注册 `pc-<房间码>`，地址与二维码出现；之前发出去的老链接立刻可用
- **拨回关**：在线外网设备收到说明并退回起始页；之后再来敲门当场回绝，不会一直「连接中」
- **房间码始终不变**，局域网 HTTP 完全不受影响

关着时房主这侧仍挂着信令连接（只是不开门），这是为了不换房间码；想彻底不碰外网，销毁房间即可。

## 用起来

| 功能 | 说明 |
|---|---|
| 文字聊天 | 带时间与发送者编号；局域网通常几十毫秒上屏 |
| 文件互传 | 多选 / 拖拽 / 粘贴上传，逐字节无损；同名自动加序号，不覆盖 |
| 发送队列 | 等待 / 传输中（百分比 + 速度 + 剩余时间）/ 失败可 ↻ 重试；外网访客要等房主确认收到才算成功 |
| 桌面共享 | 一键投屏给全房间，1080p / 30fps；后加入的人自动看，停止后卡片原地变灰 |
| 完全离线 | 把主页这份 `index.html` 发给任何设备，浏览器打开就能当访客 |

**文件不做在线预览**——预览得先把整个文件拉过来，流量和等待都白花。聊天里就是一张卡（扩展名 + 文件名 + 大小），只有右侧下载按钮能点。

- 房主 / 局域网设备发文件：走本机 HTTP 直接落盘，最快
- 外网访客发文件：分片走 WebRTC 给房主，房主收全并落盘后回执，发送端才标完成
- 下载别人的文件：访客从房主 P2P 分片拉取，卡片下方有进度条

**桌面共享**只有安全上下文（https 或 `127.0.0.1`）能发起，`http://192.168.x.x` 不行；手机通常只能看，不能发。

### 数据存在哪、留多久

```
数据/房间/<房间码>/接收文件/
```

聊天记录**只在内存里**，不落盘。一个房间一个文件夹，销毁时整个删除，**不可恢复**。销毁条件：房主点销毁、关房主页面、房主离线、60 分钟无通信。想留东西，销毁前把 `接收文件/` 拷走。纯网页房间没有磁盘，数据在房主浏览器 IndexedDB 里，房间结束即清除。

## 常见问题

**Windows 提示「已保护你的电脑」** → 下载栏点「…」→「保留」；运行时点「更多信息」→「仍要运行」。这不是查到病毒，而是没有代码签名证书、每个新版本的哈希都要从零积累声誉。嫌麻烦可右键 exe → 属性 → 勾「解除锁定」。

**微信 / QQ 里打不开链接** → 点右上角「在浏览器打开」，内置浏览器通常不支持 WebRTC。

**外网连不上** → 按提示对号入座：

| 提示 | 怎么办 |
|---|---|
| 找不到房间 | 核对 10 位房间码；确认房主页面开着；局域网房间要房主打开「外网加入」 |
| 外网已关闭 | 让房主打开「外网加入」，或改用同一 WiFi 的 `192.168.x.x:8000` |
| 连接超时 / 连不上信令服务器 | 换个网络或系统浏览器；双方都在对称 NAT 时可能打不通（只内置公共 STUN，没有 TURN） |

**怎么确认文件没被改过** → 比对文末 SHA256：`certutil -hashfile 数据传输.exe SHA256`。

## 已知限制

- 无 TURN 中继，对称 NAT / 严格企业网络下可能连不上
- 网页直连房间不支持局域网设备加入；清浏览器数据会一并丢失房间内容
- 房主是外网设备之间唯一的中继，房主关页面后外网设备之间就收不到彼此消息
- 外网访客只拿到最近 200 条历史；大文件下载期间房主要保持页面打开
- 局域网 `http://<IP>:8000` 是明文 HTTP，不适合传敏感数据
- 没有管理面板，也没有踢人；想一次清空就「销毁房间」再重新创建

完整技术说明、构建与发布流程见 **[ARCHITECTURE.md](ARCHITECTURE.md)**（给后续接手的人看）。

## 版本与校验

| 项目 | 值 |
|---|---|
| `index.html` | 480,265 B / md5 `7783cdd5` |
| `数据传输.exe` | 9,480,467 B（9.04 MB）/ sha256 `1f1a71e2…6032bc1`，版本资源 **2.0.27.0** |
| 页面指纹 | `2005049296` |

**2.0.27（当前版本）**：大文件传输的三处硬伤修复。① **心跳与分片抢通道**：房主端每 5 秒发的 `PING` 和文件分片共用同一条可靠有序的 DataChannel，传大文件时 `PING` 排在数千条分片后面，`PONG` 迟迟不回，60 秒后连接被判「人已离开」并摘掉——这是大文件中途掉线的真因；现在只要连接还有字节在流动就跳过 PING 判死，真卡死改由「120 秒毫无变化」兜底。② **接收缓冲改为 Blob 分批**：以前把每片 `ArrayBuffer` 直接塞进数组，1 GB 文件峰值占用翻倍、手机上必 OOM，改为每 2 MB 合成一个 Blob，数据交给 blob 存储（可落盘），V8 堆压力降一个量级。③ **断点语义补齐**：未收完的文件被新的 `FILE_META` 顶掉、或连接被判死时，都立刻回 `FILE_NAK`，不再让发送端干等 20～90 秒的回执超时。另：发送端预读从 1 片改成 2 片双缓冲；加入重试 3 次→5 次（约 25 秒窗口）、通道软重试 3→4 次、断线自动重连 4→6 轮；「还没收到 WELCOME 就断开」不再直接踢回入口页，先自动重连。

> **2.0.26**：在线入口回到 **GitHub Pages**（`https://zvzqvqdvd.github.io/data-transmission/`）。阿里云 ESA 的站点区域只能选「全球／不含中国大陆」，实际落到香港节点并回源 OSS，实测整页 3.57 s（GitHub 1.65 s）；且每次发布要「传 OSS + 刷缓存」两步，容易漏，本次核对线上仍停在 2.0.23。改动只有 `client_url.txt` 一行 + 重新导出页面，**代码零改动**，传输链路不变。

> **2.0.25**：在线入口换成自有域名 `https://zvzqvqdvd.top/`（阿里云 ESA，全球节点、无需备案）；后端跨域白名单改为**同一主机同时放行 http 与 https**，证书没配好或用 `http://` 打开时也不会表现成「页面能开但连不上本机程序」。传输链路无改动。

> **2.0.24**：站点从 GitHub Pages 迁到**阿里云「函数和 Pages」**；`gate.js` 里写死的 GitHub 备下载地址改成按当前页面目录推导，以后换域名不会再留下死链。

> **2.0.23**：纯外网链路四处修复——发送背压改成事件驱动；进度条刷新降到 10 Hz；**房主刷新页面时访客不再被踢回起始页**；手机切后台回来若连接已死会立刻重连。

> **2.0.21**：信令断开不再影响已建立的通道，退出/刷新主动道别（`BYE`），离线判定放宽到 60 秒且后台不计；房主端信令重连失败时不再换码踢人；新增 TURN 中继兜底。

> 页面与 exe 要成对更新。点顶栏「房间说明」看底部「页面版本」，应与上表指纹一致；线上对不上就是没覆盖上传或被缓存了。
